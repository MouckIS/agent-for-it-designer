# 存量 SaaS 专项分析

十年期系统的风险主要不在新功能，而在「看不见的存量约束」。本 Skill 提供跨阶段共用的 SaaS 基线检查面。

与项目检查项的关系：项目特有检查项由 `.claude/skills/etp-project-checklist` 提供，两者叠加执行；冲突时以项目检查项为准。本 Skill 只保留行业通用基线。

## 1. 多租户

必须回答：

- 数据访问是否经过统一租户上下文？是否有人手工拼 `tenant_id`？
- 缓存 key 是否带租户前缀？跨租户缓存是否可能串读？
- MQ 消息是否携带租户？消费端是否恢复上下文？
- 异步线程池/定时任务是否传递租户？线程复用是否残留上一个租户？
- 特殊租户是否有例外逻辑？例外是否会被新逻辑绕过？

任何一项无法确认，标 `needs_runtime_confirm`。

## 2. 存量行为兼容

- 是否改变默认行为（未配置时的行为）？
- 是否改变历史状态流转或允许的历史数据进入非法状态？
- 是否影响老接口调用方（含内部服务、开放平台、脚本）？
- 是否破坏特殊租户的定制分支？
- 是否需要保留旧逻辑一段时间？保留期如何退出？

## 3. 数据库

- 是否改表结构？是否大表 DDL？是否有索引影响？
- 是否需要回填？回填期间新旧逻辑如何共存？
- 是否支持新旧版本同时运行？
- 迁移失败如何回滚？回滚后数据是否可读？

## 4. 权限

- 是否新增/修改权限点？默认授予谁？
- 是否改变已有角色权限？
- 是否存在越权读写（尤其按 id 直接查询）？
- 是否影响后台管理、导出、下载等旁路入口？

## 5. 计费与权益

- 是否影响计费口径、权益快照、套餐限制、历史账单？
- 是否存在「先退款后扣权益」这类跨域不一致？
- 是否需要补账/对账任务？

## 6. 消息与异步

- 契约是否变化？旧消费者是否仍能解析？
- 是否可能重复消费？幂等键是什么？
- 是否可能丢消息？失败是否有重试与死信？
- 历史消息回放是否兼容？

## 7. 可观测性

- 是否需要业务日志（含 traceId、租户、关键业务号）？
- 是否需要指标与告警？阈值是什么？
- 是否需要审计日志？审计字段是否完整（操作人、租户、对象、前后值）？

## 8. 运行时证据

静态分析看不到的行为：动态开关、反射、跨服务调用、特殊租户配置、Job 实际执行、接口是否仍有调用。

| 来源 | 用途 |
| --- | --- |
| API 访问记录 | 判断接口是否仍被调用 |
| Trace | 真实跨模块/跨服务链路 |
| MQ 监控 | 实际订阅关系与消费量 |
| Job 执行记录 | 任务是否真的在跑 |
| 配置中心 | 动态配置与租户差异 |
| SQL 审计 | 真实读写路径 |

没有数据时写 `evidence_gap`，禁止推断为「没有影响」。

## 9. 风险分级

见 `references/saas-checklist.md` 末尾的分级表。分级必须附理由与证据，不能只给等级。

## 10. 版本与降级

- 记录检查依据的文档版本与图谱版本。
- 图谱不可用时使用静态检索，标 `degraded`。
- 文档与代码冲突时，以基线代码为准，并标注规范可能过期。
